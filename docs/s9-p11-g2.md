# Galaxy S9 — P1.1 crash tracing + G2 safe redundant GLES bind

Branch: `s9/p11-g2-safe-bind-if-redundant` based on P1/G1
`s9/pride-userdict-glcost-p1g1`.

## Why P1.1 is diagnostic, not a SIGSEGV fix

The P1+G1 25-minute log proves that `-[NBCommandBuffer userDictionary]`
now responds to `PridePosterExtension` (six positive traces; no old
NSInvalidArgumentException), but the extension still crashes SIX times by
**SIGSEGV** in the first ~5-minute deferred launch burst. PuTTY has no crash
PC, fault address or symbolicated stack. A speculative workaround or
swallowing SIGSEGV could introduce memory corruption.

`p11_trace=1` logs, per PridePoster process, the first call to
`userDictionary`, six callstack frames with **image-relative offsets**,
the dictionary returned, and the command buffer's eventual commit,
completion and deallocation if reached. Uses only normal Objective-C
method calls (`backtrace`, `dladdr`), **not** a signal handler. It keeps
P1's already functioning dictionary and existing GPU lifecycle unchanged.
If the extension crashes after `userdict-return` without `command-commit`,
this distinguishes a caller-side/MPS transition from a commit/completion
path, but cannot prove the faulting instruction. For a complete P1.1 fix
obtain the on-device `PridePosterExtension-*.ips` crash report
(PC, FAR/exception type, crashed-thread stack, binary images with UUIDs)
and symbolicate the offsets; only then modify the failing code.

Use the `p11_trace=1` flag for this investigation only. It writes up to
about ten UART lines each call in the crashing extension, and has small
startup overhead. Do not install global exception swallowing or weaken
AMFI/thermal checks.

## G2 changes behavior ONLY when `g2_bind=1`

Prior G1, clean idle: `glBindTexture` 34,175 calls in 1,500 frames,
total 4.609s of inclusive CPU wall time (~135us/call), then
`glDrawElements` 34,170 (~109us/call) and `glFlush` 1,500
(~1.562ms/call, including `frame_end`). The GLES shim already caches
IOSurface textures and shows ~zero refills while steady.

G2 keeps a small per-context table of the last **observed real**
`GL_TEXTURE_2D` binding per texture unit (first eight). On subsequent
`my_glBindTexture` calls, it skips ONLY the actual native-driver call
if the exact texture name is already known to be bound on the same
texture unit and target. **It does not skip**:
* any of `image->used`, IOSurface seed checks, `surface_changed`,
  `surface_to_texture` or `e->bound` state updates;
* bindings with unknown/other target/texture units outside 0..7;
* texture deletion, data uploads, shader draws, `glFlush`,
  `glFinish`, fences, framebuffer ops, GPU timing or thermal caps.

Internal raw `glBindTexture` and `glDeleteTextures` calls are wrapped
only to **invalidate all cached bindings**, including blur/helper
calls and the calls that rebind textures internally. The driver calls
still occur, unchanged. The native bind state is recorded only AFTER
the real driver call. When uncertain, it always forwards to GLES.

When `g2_verify=1`, every 128th eligible redundant bind is validated
against `glGetIntegerv(GL_TEXTURE_BINDING_2D)`. On disagreement,
`hakios-gl-g2: BINDING MISMATCH...` appears and the optimization is
**permanently disabled for that context**. This adds occasional host/driver
work, so don't compare its FPS directly to an uninstrumented baseline.

Every 60 frames, `hakios-gl-g2: up=... frames=... attempted=N
skipped=N driver=N invalidated=N fault=0/1 verify=0/1` measures the
actual shortcut rate. Unlike the GL call-cost profile, it does not
measure native driver wall time; use `glcost=1` alongside it for
comparison. The default without `g2_bind=1` retains the previous
GLES renderer behavior.

**No optimization to glDrawElements or glFlush yet.** G1 cost labels
include wrapper work and may capture `frame_end`, so skipping those
would be unsafe. The first G2 step is specifically redundant binds.

## CI/build limitations and installation safety

The portable C11/C++17 tests cover per-unit state invalidation, exact
boot arguments and GPU fallback. GitHub Actions also runs syntax jobs
for both iOS frontends. **Portable tests do not prove any iOS build or
correct UI output**. Confirm iOS syntax and full installer build before
any install.

S9 installer workflow: trblsg/sios `s9-installer.yml`, workflow branch
`fix/s9-installer-device-selection`, `kernel_ref`:
`s9/p11-g2-safe-bind-if-redundant`. Keep other last-working arguments,
`metal=true`, `userdata_blocks=starlte=13917184`,
`time_limit=0`, FPS logging enabled.

Both G2 and P1.1 modify **userland**, not just kernel. First install
requires compatible root/SYSTEM images containing new EAGL and Metal
dylibs. Check build's `userland.log` for binary placement: files above
root APFS's maximum file size may be promoted to SYSTEM. The existing
full installer **formats USERDATA**: back up EFS, BOOT, SYSTEM and
USERDATA off-device, confirm restore paths, don't flash full installer
just to change a boot argument. Preserve the known-good rollback build.

the patch, and capture one PuTTY file from before boot. Enable the
validation sampling during the first G2 hardware test:

    poster_retry=2 widget_nice=0 poster_probe=1 metal_layout=0 p1_userdict=1 p11_trace=1 glstage=1 glcost=1 g2_bind=1 g2_verify=1 mali_probe=1 mali_gov=1 mali_max=598 mali_dvs=0 mali_gov_frame=455

Same wallpaper, actual screen ON, brightness70, Wi-Fi, charger, room
and start temperatures as prior P1G1 test. **No touches at all** in
the first 600s so the PridePoster deferred burst at mach uptime~310s
and the clean GLES frame windows can be compared. Continue to absolute
mach uptime>=720s to verify the late steady interval; the extended
poster sampler can be left running longer if slow cooling is the goal.

Save `putty-P11G2-455.log`. Key markers:
* `native-metal-p11: userdict-enter`, callstack
  `native-metal-p11: stack[...]`, `userdict-return`, maybe
  `command-commit`, `command-finish`, `command-dealloc`.
* `PridePosterExtension` still has any `SIGSEGV`? If yes,
  **obtain the CrashReporter .ips** for symbolication.
* `hakios-gl-g2: enabled`, `attempted`, `skipped`,
  `invalidated`, `fault`, `BINDING MISMATCH`.
* `hakios-gl-cost:` bind CPU cost and `hakios-gl-stage:` total
  vs prior P1G1 log; compare ONLY same absolute mach uptime and
  equal workload. Differences in initial battery/SoC temperature,
  touches or profiler flags make heat/FPS comparison inconclusive.
* Maintain `mali_probe`, `poster_cost`, `fps_log` as before;
  do not turn off thermal caps or introduce mali_dvs.

**Stop and return to the P1/G1 known-good build** if icons/textures
appear wrong, screen is blank/partial, crash restarts accelerate,
GPU faults or `BINDING MISMATCH` occurs. An isolated faster benchmark
is not proof of display correctness. Keep screenshots of unchanged
home screen and Settings pages for visual comparison.

For a later *strict* G2 efficacy check, keep the same installed binary
and logging flags, only change `g2_bind=1` to `g2_bind=0`
(and leave `g2_verify=1` to preserve the bootarg list). Do not
reflash the full userland for an argument-only A/B.
