## Evidence driving this follow-up

* P6.6 observed ~10 FPS, 28,617 draw calls/1260 EAGL frames, 2 checked
  IOSurface changes ~60s apart, but 14,220 input checks skipped. Both
  display render targets alternate; input sameness does not prove pixel sameness.
* P6.7: `glDrawElements` ~2.54ms/frame, `glBindTexture` ~1.33ms/frame,
  `glFlush` EAGL slot ~1.58ms/frame, native flush sampled path
  ~0.27ms/frame. Sampled surface check averaged 106.5µs versus
  native bind ~1.39µs; the check stage, not necessarily the GL driver
  binding itself, warrants explanation.
* The kernel Scion state log reported
  `state ms static 0 touched 0 animating 1000` even under static ~10 FPS
  at 100ms gaps. The Scion classifier sets ANIMATING when
  `frame_gap <= MOVING_MS(50)`, but a previous ANIMATING result remains
  until `quiet_ms >= STATE_STATIC_MS(300)`. A new present every 100ms
  can therefore delay exit from ANIMATING indefinitely. This is a **hypothesis**
  until the governor's *actual* event timestamps are measured.
* The `p66 not_presented=1260` EAGL path is **not** a physical
  no-scanout claim. On Mesa `hakios_gl_present()` returns 0 by design;
  independent MiniIOMobileFramebuffer `fps:` logs still showed ~10
  presented/flip accounting per second.

### P6.10 interpretation: not all 'ANIMATING' windows mean moving screen

Log `p610-gov` includes `windows`, `span_ms`, `moving`,
`anim`, `static`, `fingers`, `sticky`, `sticky_ms`,
`shadow_static`, `transitions`, `last_gap_ms`,
`last_age_ms` (frame-only age), `last_quiet_ms` (since the newest frame OR touch, which the real Scion classifier uses), `max_age_ms`, `invalid_frame`, `applied=0`.

`p610-gap` bins *actual distinct governor frame notification timestamps*:
`gap_le50`, `gap_51_150`, `gap_151_300`, `gap_gt300`,
plus distribution of **governor windows** by frame-only age (separate from Scion's latest frame-or-touch quiet age):
`age_le100`, `age_101_299`, `age_ge300`. First pre-phase
frame timestamp establishes a baseline and is **not** counted as an
event of this phase.

`sticky` is a window where the previous and actual state are ANIMATING,
`frames_moving()` is false, no fingers are down, `frame_gap>50ms`,
but both frame age and real Scion frame-or-touch quiet age are below 300ms. Windows without a valid frame timestamp are excluded. This is a **shadow diagnostic** of the
state machine's hysteresis, not a claim that switching immediately to
STATIC would preserve all performance, frame deadlines, audio, sensors
or thermal behavior. `shadow_static` is hypothetical only, never
written into the actual Scion governor. Read both
`cpufreq_gov: state ms ...` and `p610-gov` to cross-validate.

The old baseline code logs this Scion state only when `gov_policy`
chooses the Scion path; ensure the **unchanged** tested governor
policy is active, do not alter it just to make the test show data.

### P6.11 skip reasons and 1:16 checksum timing

A call to `surface_changed` is placed into exactly one of these
non-overlapping categories:

* `skip_sameframe`: IOSurface already checked this EAGL frame
* `skip_no_base`: no CPU base address
* `skip_planar`: planar image, outside this checksum path
* `skip_seldom`: the existing `STILL_LOOKS=120` /
  `STILL_EVERY=8` stable-input sampling policy skipped this occasion
* `checked`: original checksum was performed; split into
  `checked_same` and `checked_changed`

Only one of each 16 **executed checksum** calls is timed; `samples`
counts timed calls, `sample_bytes`, `sample_us`, `max_us` the
bytes/time measured. The `p611-surface` lines identify the sampled
IOSurface ID and sampled bytes/time, not all the surface's work.
There are eight bounded surface tracking slots per 60-frame group;
`overflow` discloses samples that could not be assigned one of them.
No distinct IOSurface is read or hashed solely for diagnostics. A
positive `skip_seldom` count means **unverified input**, not input
same, draw skipped or output pixels same.

Compare this with `p67-path` native bind and
`p66-ca` inputs from the prior run; do not sum sampled times
as if they were CPU total or GPU watts.

### P6.12 provenance boundaries

* `p612-eagl`: `frames` and `draws` at completion of
  **CoreAnimation's EAGL GL frames**. `single`/`multi`/`unknown`
  count output targets, `target_a`, `target_b`, `alternating`,
  `switched`, `same`, `third_target` describe their **identities**,
  not pixel contents or physical scanout buffers.
* `api_calls`, `api_positive`, `api_zero`, `api_negative`
  are the result of calls to `hakios_gl_present` in this EAGL path.
  The Mesa/OSMesa version returns zero by design. Do not interpret
  `api_zero` as no screen present; the framebuffer may already be
  scanning shared IOSurface buffers.
* `fps: N presented, M drawn, F flips` is **independent kernel
  framebuffer driver accounting**, already logged by the kernel.
  The offline reporter groups those logs by P6 phase. It does not
  create a new framebuffer hook and does not prove physical panel
  pixels or optical ON without additional device evidence.
* The two sources may have different buffer and timing semantics.
  An EAGL 60-frame bucket can cross a P6 phase boundary because
  runtime sysctls are polled every 60 EAGL frames. Do not demand a
  strict 1:1 count at a phase boundary, and do not use `p66
  not_presented` as a display failure test.

## One matching BOOT + SYSTEM image, repeat runtime phases

A new build is **required once** because the P6.10 governor probe
lives in kernel and P6.11/P6.12 live in updated EAGL userland.
Do not mix prior SYSTEM images with this kernel.

Retain known-working S9 build parameters and bootargs including
`poster_probe=1`, `mali_gov=1`, `mali_dvs=0`, GL/Metal settings
from the previous successful device build. If using the existing
installer workflow, branch
`fix/s9-installer-device-selection`, kernel ref
`s9/p6-unified-wake-thermal-display-lab`, `metal=true`,
`userdata_blocks=starlte=13917184`, `time_limit=0`.
The installer may **format USERDATA**: retain verified offline
BOOT, SYSTEM, EFS, USERDATA backups and a working rollback path.

New `-DeepOnly` host protocol is independent from
`-ExtendedOnly`, `-ResumeCAOnly` and actual G3D testing.
Default phase cadence (no physical power-button action):

| Phase | Time | Setting |
|---|---:|---|
| 20 | 60s | A1 screen ON; P6/P5/P610/P611/P612 OFF |
| 21 | 120s | P6.10 Scion state/time-gap shadow; P6/P5 supporting CPU/GPU proxies |
| 22 | 120s | P6.11 surface hash and skip-reason attribution |
| 23 | 120s | P6.12 EAGL target API + independent kernel fps present/flip |
| 24 | 60s | A2 observers OFF; control for baseline thermal drift |
| 9 | cleanup | set P610/P611/P612 and P6/P5/G3D modes to zero with ACK |


## Failure and rollback

For manual safe exit, each command must be ACKed by the device:

```text
sysctl kern.hakios.p610_mode=0
sysctl kern.hakios.p611_mode=0
sysctl kern.hakios.p612_mode=0
sysctl kern.hakios.p66_mode=0
sysctl kern.hakios.p67_mode=0
sysctl kern.hakios.p68_mode=0
sysctl kern.hakios.p69_mode=0
sysctl kern.hakios.g3d_lab_gate=0
sysctl kern.hakios.p6_mode=0
sysctl kern.hakios.p5_mode=0
sysctl kern.hakios.p5_threads=0
sysctl kern.hakios.p4_mode=0
```

No new optimization is claimed. A rise in temperature during a
sequential A/B experiment is **not proof** that a particular observer
generated the heat. Repeating controlled A1/A2 with the same initial
temperature is required before applying clock/gating/damage optimizations.
