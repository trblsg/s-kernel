## P0 — optimized all-byte checksum

Boot flag p0hash=1 enables s9_ioshash4_fast. It updates four independent
64-bit hash accumulators per 32-byte block. This reduces serial multiply/
shift dependencies and gives ARM64 room for instruction-level parallelism.
It hashes ALL bytes, including trailing 1..7 bytes ignored by the old
algorithm. A scalar implementation in s9_ioshash4.h generates the EXACT
SAME NEW digest as the four-lane fast implementation. This 64-bit checksum
is non-cryptographic and probabilistic, like the old one; no hash can
guarantee zero collisions.

The old IOSurface seed check, full scan decision, STILL_LOOKS=120,
STILL_EVERY=8, per-surface saved checksum, texture refill, GL commands and
frame sync are unchanged. p0hash=0 (or absent) runs the original loop
byte-for-byte, supporting controlled A/B from the same installed images.

Recommended safety flag p0verify=1 rechecks every 128th actual checksum
using the scalar four-lane reference. On mismatch, logs once, forces a
dirty update and permanently uses the scalar reference for subsequent
checksums in that process. Both four-lane implementations have identical
digest representation; no baseline reset is needed on fallback.
Concurrent IOSurface writers can also provoke a conservative mismatch;
this should cause more work, never intentionally skip an upload.

Once per 60 frames the new hakios-gl-p0 line reports fast/scalar/verified/
mismatch/fallback. Existing glhash=1 gives sampled CPU time per hash.
On-device profiling adds a small burden due to verification and timers;
a true power/performance decision requires controlled repeated trials.

## P1 — observational MPS crash diagnostics

p1_mps_diag=1 captures the class names (not string content or values)
of up to three entries in the NBCommandBuffer userDictionary at its SECOND
read, along with the current committed state. It does not change
dictionary contents, ownership or lifetime, register a SIGSEGV handler,
create Metal objects, or alter renderer behavior. It works independently
of p12_diag=1; keep p1_userdict=1, p11_trace=1, p12_diag=1 for correlation.

Expected line: native-metal-p1mps: command=... read=2 entries=1
key_class=... value_class=... committed=0. That is NOT the SIGSEGV PC.
Need an on-device PridePosterExtension*.ips crash report containing
exception subtype/FAR, PC, crashed-thread stack and binary-image UUIDs
to fix the actual MPSImage error.

## P3 — read-only actual G3D power state, NOT power-control

p3power=1 with mali_probe=1 emits one mali-power line every existing
five-second governor sampling interval. It reads read-only PMU G3D
status/config and CMU_G3D PLL enabled/stable/mux state, the G3D driver's
awake flag, age of last frame/job, reported framefloor and clock. PMU
and CMU_G3D registers reside OUTSIDE the Mali power domain; do not access
GPU MMIO when the GPU could be off. No g3d_sleep enable, no rail write,
no PLL switch, and NO changes to thermal cap, governor or clock floor.

Optional p3rail=1 performs read-only B6CTRL and B6OUT PMIC ACPM reads
at most once per 30 seconds and prints last measured voltage. To avoid
any ACPM traffic perturbing P0, leave p3rail=0 for the first experiment.
rail_mv_last=0 with rail_read=0 indicates NOT MEASURED, not 0mV.
Neither GPU frequency nor voltage quantifies wattage absent rail current.

P2 GL draws and frame_end: INTENTIONALLY NOT CHANGED in this branch.
